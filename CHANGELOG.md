# Changelog

## [Unreleased]

### 2026-09-14

- Правила проекта `cline/clinerules.md` переписаны под специфику репозитория
  (итерация ITER-20260914221557):
  - удалён раздел Memory Bank (в репозитории его не было); итерации и
    `CHANGELOG.md` сохранены, добавлено правило создания `CHANGELOG.md` при
    первой записи;
  - добавлены разделы: компоненты и инварианты проекта (побайтовый паритет
    C++ ↔ Python, упаковка `rgb`/LAS, экстраинсики `A_from_B`, диалекты
    `config.yaml`/`calibration.yaml`, `/colorised_points` в кадре `os_sensor`),
    публичные интерфейсы, сборка и окружение, валидация, данные и
    игнорируемые артефакты;
  - удалены чужие фрагменты: каталоги `docs`/`temp`, раздел про
    `calibrate.py`, пример коммита из JS-проекта.
- Создан `CHANGELOG.md` (файл отсутствовал).
- В корень добавлен `.clinerules` — короткий указатель на `cline/clinerules.md`,
  чтобы правила проекта подхватывались агентом (итерация ITER-20260914222313).
- Исправлено форматирование `cline/clinerules.md`: в §3 отсутствовала пустая
  строка перед разделителем `---`, из-за чего абзац про тяжёлые прогоны
  рендерился как заголовок (итерация ITER-20260914224227).
- Добавлено приложение `ColoriseMap/` — ROS-free раскраска готовой карты точек,
  повторяющая логику узла `src/ColoriseMap.cpp` (итерация ITER-20260914232359):
  - цель cmake `colorise_map` собирает приложение вместе с уже проверенными
    исходниками `colorise/` (io/trajectory/project) — проекционное ядро не
    дублируется, `colorise/` не изменялся;
  - офлайн-ключи как у `colorise_offline` (`--cloud/--photos/--camera/--calib/
    --trajectory/--output`), многокамерность — повторяемыми тройками
    `--photos/--camera/--calib`, пары кадров по `--max-time-offset`;
  - режимы компенсации `none|odom` (IMU-режим узла не переносится: в данных
    репозитория нет AHRS-ориентации, траектория и так ~200 Гц);
  - `--map-max-range`, `--min-color-frames`, z-буфер окклюзии,
    `--keep-uncolored`, сохранение в PCD/LAS в конце прогона;
  - проверено: побайтовый паритет выходного PCD и всех 82 строк `[frame N]` с
    `colorise_offline` (1 201 612 точек, 99.57 %), детерминизм `--jobs`,
    порог `--min-color-frames 2`, корректный `.las` (LAS 1.2 fmt 3).

### 2026-09-15

- Изменён формат идентификатора итерации: `ITER-YYYYMMDD-hhmiss` вместо
  `ITER-YYYYMMDDhhmiss` (итерация ITER-20260915-132202). Обновлены шаблон
  YAML-файла итерации, шаблоны сообщения коммита и путь восстановления после
  сбоя; исправлен устаревший пример сообщения коммита, остававшийся в старом
  формате.
- Удалён `run-colorise.sh` (серия из 192 прогонов по матрице параметров) — по
  решению пользователя (итерация ITER-20260915-140547). Из `cline/clinerules.md`
  убраны ссылки на него: §1.1 (таблица компонентов), §1.3 (публичные интерфейсы),
  §2.4 (подраздел «Скрипт серии прогонов» удалён), §3 (перечень тяжёлых операций)
  и раздел «Специфика этого репозитория».
- Добавлен `make_photo_plane.py` — генератор тестовой фикстуры для проверки
  алгоритмов раскраски (итерация ITER-20260915-231427): облако точек в плоскости,
  параллельной плоскости изображения выбранного снимка (`--distance`, `--ppm`),
  плюс эталонный sidecar с ожидаемыми пикселями и цветами. Скрипт ничего не
  раскрашивает, загрузчики переиспользованы из `colorise_offline.py`. Проверено:
  при прогоне только по эталонному кадру `coloured` совпадает с числом точек
  «внутри кадра», генерация детерминирована, отказы корректны.
- `make_photo_plane.py` переведён на потоковую генерацию (итерация
  ITER-20260915-232725): точки считаются порциями (`--chunk`, по умолчанию 1000)
  и сразу пишутся в PCD и эталонный CSV, поэтому память не зависит от размера
  фикстуры. Результат не изменился: облако и эталон побайтово совпадают с прежней
  версией при любом размере порции; пик памяти одинаков для 115 тыс. и 2.3 млн
  точек.
