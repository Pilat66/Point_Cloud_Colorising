# make_photo_plane.py — генератор фикстуры «облако в плоскости снимка»

Скрипт готовит **детерминированное** облако точек в плоскости, параллельной
плоскости изображения выбранного снимка, на заданном расстоянии от камеры
(при необходимости — наклонённой). Скрипт **ничего не раскрашивает**: его
результат — вход для алгоритмов раскраски.

Зачем: одно и то же облако прогоняется через несколько реализаций
(`colorise_offline` C++, `colorise_offline.py`, `ColoriseMap`) — так проверяются
побайтовый паритет, гейты и качество выборки цвета на заранее известной
геометрии. Плоскость строится по реальным углам кадра и модели дисторсии, поэтому
известно, какие точки обязаны попасть в кадр и в какой пиксель.

Генерация потоковая (`--chunk`, по умолчанию 1000 точек за заход), поэтому память
не зависит от размера фикстуры.

---

## 1. Зависимости

```bash
pip install numpy opencv-python
```

Загрузчики (траектория, `calib.json`, время снимка из имени файла, камера из блока
`camera`) переиспользуются из `colorise_offline.py` — импорт безопасен, там всё под
`if __name__ == "__main__"`.

Не нужны для этого скрипта: `pyyaml` (камера читается из `calib.json`), `scipy`
(кадрирование по радиусу не выполняется) и `laspy` (облако не читается — только
пишется PCD).

## 2. Быстрый старт

```bash
venv/bin/python make_photo_plane.py data/img-1789476925898092722/1789476925898092722.png \
    --trajectory data/trajectory.csv --calib data/calib.json \
    --distance 5 --ppm 100 --output /tmp/plane.pcd
```

При наклоне плоскости (30° вокруг X, 20° вокруг Y):

```bash
venv/bin/python make_photo_plane.py data/img-1789476925898092722/1789476925898092722.png \
    --trajectory data/trajectory.csv --calib data/calib.json \
    --distance 5 --ppm 100 --tilt-x 30 --tilt-y 20
```

Что печатает прогон по умолчанию (кадр 1600×1300, `--distance 5 --ppm 100`):

```text

[photo-frame] 100 точек по периметру кадра (25 на сторону), z = 5 м
[plane] 9.40 x 7.66 м, шаг сетки 0.1000 м, сетка 95x78
[stats] точек 7510  (в кадре ожидается ~6191 при площади кадра 61.9 м²)
```

## 3. Как строится облако

### 3.1 Плоскость и сетка

1. Пиксели переводятся в лучи: `cv2.undistortPoints` (или
   `cv2.fisheye.undistortPoints` для модели с `fish`/`equidistant`) по модели и
   дисторсии из блока `camera` файла `--calib` — см.
   `colorise_offline_README.md` §3.3.
2. Лучи через четыре угла кадра `(0,0)`, `(w−1,0)`, `(w−1,h−1)`, `(0,h−1)`
   пересекаются с плоскостью `z = --distance` (в кадре камеры). Центр прямоугольника
   `(cx, cy)` — середина этих пересечений, полуразмеры умножаются на `--margin`
   (по умолчанию `1.05`: часть точек намеренно выходит за кадр, чтобы проверить
   гейт по краю изображения).
3. Сетка: шаг `1/√(--ppm)` м, `nx = round(2·hx/step) + 1`, `ny = round(2·hy/step) + 1`,
   точки центрируются по прямоугольнику. Плотность — ровно `--ppm` точек на
   квадратный метр **плоскости**.
4. Точки в кадре камеры: `p_cam = (x, y, --distance)` (или см. §4 при наклоне),
   затем в мир: `p_world = R_wc · p_cam + o_wc`.

### 3.2 Поза камеры

- Время снимка берётся из его имени: эпоха в нс/мс/с, определяется автоматически
  (самая длинная цифровая группа имени), как в `colorise_offline`.
- Поза лидара `T_world_lidar(t)` интерполируется по `--trajectory`
  (LERP по позиции + SLERP по кватерниону); если время снимка вышло за
  траекторию не дальше `--time-tolerance`, поза зажимается к ближайшему концу
  (печатается WARN), иначе — ошибка. `--time-shift` сдвигает время траектории.
- Экстраинсик — из того же `--calib` (`results.T_lidar_camera` и т.п.):
  `T_world_cam = T_world_lidar(t) · T_cam_lidar⁻¹`.
- Форматы траектории и направления экстраинсика — как в `colorise_offline`
  (`colorise_offline_README.md` §3.2 и §3.4), включая `--euler-order`,
  `--euler-units`, `--extrinsic-name`, `--extrinsic-direction`.

### 3.3 Имя выходного файла

```text
<имя фото>-plane-<distance>m-<ppm>ppm.pcd                   без наклона
<имя фото>-plane-<distance>m-<ppm>ppm-tilt<X>x<Y>deg.pcd    с наклоном
```

Например `1789476925898092722-plane-5m-100ppm.pcd`. Переопределяется `--output`
Например `1789476925898092722-plane-5m-100ppm.pcd`. Переопределяется `--output`
(каталоги создаются автоматически).

## 4. Наклон плоскости (`--tilt-x`, `--tilt-y`)

По умолчанию плоскость перпендикулярна оптической оси. Опции `--tilt-x <deg>` и
`--tilt-y <deg>` наклоняют её вокруг осей **X и Y системы камеры** (правило
правой руки, порядок поворотов фиксирован: `R_tilt = Ry(--tilt-y) · Rx(--tilt-x)`
— сначала X, затем Y).

Семантика:

- точка привязки не меняется — плоскость проходит через прежний центр
  `(cx, cy, --distance)` на оптической оси, наклоняется только нормаль
  `n = R_tilt · (0, 0, 1)`;
- базис плоскости — первые два столбца `R_tilt` (`e1`, `e2`);
- границы сетки пересчитываются: лучи через углы кадра пересекаются уже с
  наклонённой плоскостью (`λ = (n·pivot)/(n·d)`, где `d` — направление луча),
  координаты пересечений проецируются на `e1`/`e2`, по четырём углам берётся
  охватывающий прямоугольник (умноженный на `--margin`). Поэтому фикстура
  по-прежнему покрывает весь кадр, включая дальний угол.

Следствия:

1. **Пятно кадра на плоскости — четырёхугольник**, а сетка прямоугольная
   (охватывающий прямоугольник): площадь сетки и число точек растут быстрее
   пятна, как `1/cos(наклона)`. Реальные числа для этой камеры
   (`--distance 5 --ppm 100`):

   | Наклон | точек | размер сетки | дальний угол кадра |
   |---|---|---|---|
   | 0/0 | 7 510 | 9.40×7.66 м | 7.9 м (луч до угла) |
   | `--tilt-x 30` | 18 030 | 16.22×10.86 м | 13.5 м |
   | `--tilt-y 20` | 12 644 | 11.05×11.09 м | 11.2 м |
   | `--tilt-x 30 --tilt-y 20` | 65 640 | 28.88×22.53 м | 32.0 м (WARN) |
   | `--tilt-x 50` | 411 444 | 75.12×54.58 м | 65.8 м (WARN) |

Столбец «дальний угол» — длина луча от камеры до самого дальнего угла пятна
кадра на плоскости (строка `[plane-tilt]`).

2. Дальний угол при больших наклонах выходит за дефолтный `--max-range 20`
   раскраски — такие точки не будут раскрашены; печатается WARN. Практический
   предел для `--distance 5` — наклон до ~55°.
3. Маркер кадра (100 точек по периметру) **остаётся перпендикулярным** оси на
   `z = --distance` — он отмечает место снимка и при проекции по-прежнему
   совпадает с границей кадра.

---

## 5. Выходной формат и маркер кадра

Выход — бинарный PCD `x y z intensity rgb` (`intensity = 0`, `rgb = 0`):
раскраска его заполняет. В конце облака — 100 точек рамки (25 на сторону),
в той же плоскости и на том же расстоянии: по ним видно, где находится
«виртуальная фотография».

---

## 6. Предохранители и предупреждения

| Условие | Реакция |
|---|---|
| `\|tilt\| ≥ 90°` | ошибка, exit 1 (плоскость становится параллельна лучам/уходит за камеру) |
| Луч угла кадра не пересекает плоскость перед камерой | ошибка с подсказкой уменьшить наклон |
| Сетка превысила 100 млн точек (`MAX_GRID_POINTS`) | ошибка с подсказкой уменьшить `--ppm` |
| Дальний угол дальше 20 м | `[WARN]` — дефолтный `--max-range` раскраски эти точки не возьмёт |
| Время снимка вне траектории в пределах `--time-tolerance` | `[WARN]`, поза зажата к концу траектории |
| `--margin < 1.0` | `[WARN]` — края кадра не покрыты точками |
| `--distance ≤ 2.0` | `[WARN]` — при `--min-camera-dist 2` точки не раскрасятся |

## 7. Использование в проверках

1. Сгенерировать фикстуру (с наклоном или без).
2. Прогнать раскраску: `./colorise/build/colorise_offline --cloud <фикстура>.pcd
   --photos <каталог снимка> --trajectory data/trajectory.csv --calib
   data/calib.json --max-range 0 --output out.pcd` (и то же Python-версией /
   `colorise_map`).
3. Проверки, которые фиксира позволяет: побайтовый паритет реализаций,
   доля окрашенных точек (все точки в кадре обязаны получить цвет),
   соответствие цвета каждой точки пикселю (известен заранее — точка строилась
   по лучу конкретного пикселя).

Детерминизм: фикстура зависит только от входных файлов и аргументов — повторный
прогон даёт побайтово тот же файл (проверено, `cmp`).

## 8. Аргументы

| Аргумент | По умолчанию | Что это |
|---|---|---|
| `photo` (позиционный) | — | файл снимка; время съёмки — в имени (эпоха) |
| `--trajectory` | `trajectory.csv` | CSV с позами лидара |
| `--calib` | `calib.json` | камера (блок `camera`) + экстраинсик камера↔лидар |
| `--distance` | — (обяз.) | расстояние от камеры до плоскости, м, по оптической оси |
| `--ppm` | — (обяз.) | точек на квадратный метр плоскости |
| `--tilt-x` / `--tilt-y` | `0.0` | наклон плоскости вокруг осей X/Y камеры, градусы |
| `--margin` | `1.05` | запас за границы кадра, доли (1.0 = ровно по углам) |
| `--output` | автоген | путь к выходному PCD |
| `--chunk` | `1000` | точек за один потоковый заход |
| `--time-tolerance` | `1.0` | с; допуск выхода времени снимка за траекторию |
| `--time-shift` | `0.0` | с; сдвиг времени траектории |
| `--extrinsic-name` | авто | ключ экстраинсика в `calib.json` |
| `--extrinsic-direction` | авто | `camera_from_lidar` / `lidar_from_camera` |
| `--euler-order` | `xyz` | порядок Эйлеров траектории (`xyz` / `zyx`) |
| `--euler-units` | `auto` | единицы углов траектории (`auto` / `deg` / `rad`) |

Флаг `--camera` отсутствует: интринсики читаются из блока `camera` файла
`--calib` (см. `colorise_offline_README.md` §3.3), `camera.yaml` не используется.

(каталоги создаются автоматически).
