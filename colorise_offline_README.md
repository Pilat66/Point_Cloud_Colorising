# colorise_offline.py — автономная раскраска облака точек

Офлайн-инструмент раскрашивает облако точек по набору фотографий с временными
метками и файлу траектории лидара. Это ROS-free реализация проекционного ядра
`projectAndSample` из пакета (`src/colorise.cpp`): гейты по дистанции/углу/краю,
проекция камеры, z-буфер окклюзии, усреднение цвета по кадрам.

Никакого ROS / сборки не требуется — нужен только Python.

---

## 1. Зависимости

```bash
pip install numpy opencv-python pyyaml
```

Опционально:

| Пакет | Зачем |
|---|---|
| `scipy` | радиусное кадрирование вокруг камеры (`--max-range`); без него облако обрабатывается целиком |
| `laspy` | чтение входного облака в формате `.las` (для `.pcd` не нужен) |

Проверено на Python 3.12, OpenCV 4.x.

---

## 2. Быстрый старт

Из корня репозитория (в `data/` лежат примеры):

```bash
python3 colorise_offline.py \
    --cloud data/all_raw_points.pcd \
    --photos data \
    --trajectory data/trajectory.csv \
    --camera data/camera.yaml \
    --calib data/calib.json \
    --output coloured.pcd
```

Результат — файл `coloured.pcd` (поля `x y z intensity rgb`). Все аргументы
имеют совпадающие с примером значения по умолчанию, поэтому команда работает
как есть: `python3 colorise_offline.py --output coloured.pcd`.

## 3. Входные данные

| Аргумент | По умолчанию | Что это |
|---|---|---|
| `--cloud` | `data/all_raw_points.pcd` | облако точек, `.pcd` или `.las` |
| `--photos` | `data` | каталог со снимками, время в имени файла |
| `--trajectory` | `data/trajectory.csv` | позы лидара |
| `--camera` | `data/camera.yaml` | интринсики камеры |
| `--calib` | `data/calib.json` | экстраинсики камера↔лидар |
| `--output` | `coloured.pcd` | выходной PCD |

### 3.1 Фотографии

Время снимка берётся **из имени файла** — эпоха в наносекундах:

```
1788882722018994333.png     -> t = 1788882722.018994333 s
1789134128765244335.jpg     -> t = 1789134128.7652445  s
```

Поддерживаются расширения `.jpg/.jpeg/.png/.bmp`. Допускаются имена вида
`IMAGE_<ts>.jpg` (берётся самая длинная цифровая группа). Единицы определяются
автоматически: `≥1e15` — наносекунды, `≥1e11` — миллисекунды, иначе — секунды.

### 3.2 Траектория

Два поддерживаемых формата:

```
# углы Эйлера, разделитель ";", 7 колонок
time;x;y;z;roll;pitch;yaw
1788882722.933357477;0;0;0;0;0;0

# кватернион, разделитель ",", 8 колонок
time,x,y,z,qx,qy,qz,qw
1770728769.869573,0,0,0,0.012707,-0.006916,0.000088,0.999895
```

Формат определяется автоматически. Для углов Эйлера:

- `--euler-units auto|deg|rad` — единицы (по умолчанию автоопределение по
  величине углов; если определить нельзя — «градусы»);
- `--euler-order xyz|zyx` — порядок поворотов (по умолчанию `xyz` = `Rz(yaw)·Ry(pitch)·Rx(roll)`).

Поза лидара интерполируется на момент времени снимка (линейно по позиции,
SLERP по кватерниону). Снимок вне временного диапазона траектории пропускается.

### 3.3 Камера (`camera.yaml`)

```yaml
cam_model: PinholeCamera      # или FisheyeCamera / camera_model
cam_width: 1600
cam_height: 1300
cam_fx: 922.459146
cam_fy: 922.7803404
cam_cx: 797.0834849
cam_cy: 626.8043673
cam_d0: 0.04070139073         # k1
cam_d1: 0.03099759412         # k2
cam_d2: -0.008212424786       # p1
cam_d3: 0.002776078604        # p2
cam_d4: -0.1332834779         # k3
```

Поддерживается и блок `distortion_coeffs`. Если в названии модели есть
`fish`/`equidistant` — используется проекция рыбьего глаза `cv2.fisheye`, иначе
стандартная `cv2.projectPoints` (пинхол/plumb_bob). Число коэффициентов — 4, 5
или 8.

### 3.4 Экстраинсики (`calib.json`) — направление преобразования

По соглашению `direct_visual_lidar_calibration` / FAST-LIVO2:

> **`T_camera_lidar` отображает точки из системы координат лидара в систему
> координат камеры** (нотация «A_from_B»). Это ровно то преобразование, что
> нужно для проекции, поэтому оно используется **без инверсии**.

Скрипт автоматически определяет направление по имени ключа:

| Имя ключа | Трактовка | Действие |
|---|---|---|
| `...camera_lidar`, `...cam_lidar` | camera-from-lidar | используется как есть |
| `...lidar_camera`, `...lidar_from_cam` | lidar-from-camera | инвертируется |

Пример `data/calib.json` хранит зеркальное имя `results.T_lidar_camera`
(7 чисел `x,y,z,qx,qy,qz,qw`) — оно корректно инвертируется автоматически.

Поддерживаемые представления:

- 7 элементов: позиция `[x,y,z]` + кватернион `[qx,qy,qz,qw]`;
- объект `{rotation/quaternion, translation}` (или `R/t`);
- объект `{matrix: 4×4}`;
- плоский список на 12 или 16 чисел.

Направление можно задать явно: `--extrinsic-direction camera_from_lidar|lidar_from_camera`.
Нужный ключ — через `--extrinsic-name T_camera_lidar` (по умолчанию ищутся
`T_camera_lidar` / `T_lidar_camera` / `T_lidar_cam` / `T_cam_lidar`).

### 3.5 Облако точек

- `.pcd` — читается напрямую, произвольный набор полей `x y z [nx ny nz]
  intensity [curvature …]` (float / uint).
- `.las` — читается через `laspy` (установить отдельно).

## 4. Параметры CLI

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--max-range` | `20.0` | радиус кадрирования вокруг камеры, м (`0` — отключить) |
| `--min-camera-dist` | `2.0` | точки ближе камеры не раскрашиваются, м |
| `--max-view-angle` | `75.0` | полуугол обзора от оптической оси, град. (`180` — всё) |
| `--edge-margin` | `0.0` | обрезка краёв изображения, px |
| `--occlusion` | вкл. | z-буфер окклюзии (стены перед объектом не «просвечивают») |
| `--occlusion-cell` | `4.0` | размер ячейки z-буфера, px |
| `--occlusion-depth-tol` | `0.3` | допустимый разброс глубины в ячейке, м |
| `--min-color-frames` | `1` | сколько кадров должно увидеть точку, чтобы её сохранить |
| `--keep-uncolored` | выкл. | сохранять неокрашенные точки как чёрные |
| `--first-wins` | выкл. | не усреднять: точка хранит цвет **первого** кадра, который её увидел |
| `--max-lidar-z` | `inf` | отсечка по высоте в кадре лидара, м |
| `--time-shift` | `0.0` | сдвиг времени фото (с) для выравнивания разных прогонов |
| `--time-tolerance` | `1.0` | с; если снимок не дальше этого от интервала траектории, поза зажимается к ближайшей концевой точке |
| `--preview` | — | путь для PNG-превью (подвыборка 3D) |

---

## 5. Выход

PCD в бинарном виде с полями:

```
FIELDS x y z intensity rgb
SIZE   4 4 4 4   4
TYPE   F F F F  U
```

`rgb` — упакованный `uint32` (PCL-соглашение): `(R << 16) | (G << 8) | B`.
По умолчанию, если точку увидело несколько кадров, цвет усредняется по
наблюдениям. Флаг `--first-wins` отключает усреднение: точка сохраняет цвет
**первого** кадра, который её увидел (повторно не перекрашивается).

## 6. Типичные проблемы

| Симптом | Причина / решение |
|---|---|
| `coloured=0`, покрытие 0 % | Либо фото и траектория из **разных прогонов** (проверить диапазоны в логе `[photos]`/`[trajectory]`, выровнять через `--time-shift`), либо `--min-color-frames` выше числа реально задействованных кадров — скрипт в этом случае печатает WARN; для малого числа фото ставьте `1`. |
| «No points within ... m» | `--max-range` мал или камера далеко от облака (проверить `--extrinsic-direction`). |
| Цвет «плывёт» по рёбрам | Увеличить `--min-camera-dist`, `--occlusion`, `--min-color-frames`. |
| Проекция «зашумлена» у краёв | Увеличить `--edge-margin` и снизить `--max-view-angle`. |
| Выходной `rgb` не совпадает с фото | Проверить направление экстраинсиков (см. 3.4) и порядок углов `--euler-order`. |
| Нет данных для `.las` | `pip install laspy`. |

При старте скрипт печатает сводку по каждому блоку (`[camera]`, `[extrinsic]`,
`[trajectory]`, `[photos]`, `[cloud]`) — сверьте их с ожидаемыми значениями и
совпадением временных интервалов.
