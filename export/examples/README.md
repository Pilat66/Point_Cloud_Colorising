# Пример данных

Реальный фрагмент набора репозитория-источника, чтобы режим можно было
запустить и увидеть результат без гигабайтов данных.

| Файл | Что это |
|---|---|
| `map.las` | 269 487 точек с `gps_time` в окне 1.5 с (1789476757.438…1789476758.938), вырезаны из `data/all_raw_points.las`; LAS 1.4 fmt 7, те же scale/offset, координаты int32, intensity и время сохранены как есть |
| `photos/` | три подряд идущих кадра из `data/img-uniq` (1789476757.688, 1789476758.288, 1789476758.688) |
| `trajectory.csv` | позы лидара этого окна (300 строк, тот же формат `time;x;y;z;roll;pitch;yaw`) |
| `calib.json` | копия `data/calib.json` (интринсики 1600×1300 + `T_lidar_camera`) |
| `golden/` | эталонные выходы и контрольные суммы прогона |
| `make_examples.py` | генератор: пересобирает `map.las`, `photos/`, `trajectory.csv`, `calib.json` из данных репозитория |

## Как пересобрать

```bash
python3 examples/make_examples.py            # из каталога export/
# или с явными путями и другим окном:
python3 examples/make_examples.py --data /path/to/Point_Cloud_Colorising/data \
    --photos 3 --margin 0.25
```

Скрипту нужны `laspy` и `numpy` (только для генерации; самому режиму они не
нужны). Он выбирает первый кластер из `--photos` снимков подряд (внутри
интервала траектории, разброс не больше `--max-cluster-span`) и вырезает окно
`± --margin` вокруг него. Пути по умолчанию вычисляются от расположения
скрипта, абсолютных путей внутри нет.

## Сколько стоит прогон

Полный пример — 269 487 точек, 3 кадра, 6 778 кубов: **0.5 с** и ~30 МБ RSS,
окрашено ~25 % точек (остальные вне конуса камеры 1600×1300 и за z-буфером).
На полной карте репозитория (56 154 407 точек, 258 кадров) — 1:31 и ~2 ГБ RSS.
